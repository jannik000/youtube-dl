# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is not the youtube-dl source. It is a **Docker image** (published as `ghcr.io/jannik000/youtube-dl`) that wraps [yt-dlp](https://github.com/yt-dlp/yt-dlp) to download YouTube subscriptions or channels on an interval, with an optional FastAPI web UI. It is a security-hardened fork of `Jeeaaasus/youtube-dl` (MIT); `SECURITY-REVIEW.md` lists the findings and fixes. Everything under `root/` is copied into `/` of the image (`COPY root/ /`), so `root/app/...` becomes `/app/...` in the container, and so on.

## Commands

```bash
# Web UI + validator tests (pinned deps plus the yt-dlp version the images use)
pip install -r root/app/requirements.txt "yt-dlp[default]==$(cat release-versions/latest.txt)" pytest httpx
pytest -q root/app/youtube-dl-webui/tests
pytest -q root/app/youtube-dl-webui/tests/test_webui.py::test_api_token_is_csrf_exempt   # single test
# Strict yt-dlp contract test as in CI/release (fails instead of skipping; loopback server only)
YTDLP_CONTRACT_VERSION="$(cat release-versions/latest.txt)" pytest -q root/app/youtube-dl-webui/tests/test_ytdlp_contract.py

# Shell lint (CI runs exactly this)
shellcheck --severity=warning root/entrypoint.sh root/app/youtube-dl/*.sh root/etc/cont-init.d/* \
  root/etc/supervisor/terminate.sh tests/e2e/run.sh

# Dependency audit
pip-audit -r root/app/requirements.txt --strict

# End-to-end: builds the image and tests running containers (needs a Docker daemon that can build)
bash tests/e2e/run.sh
#   E2E_SKIP_BUILD=1 E2E_IMAGE=<tag>  -> test an existing image
#   E2E_BUILD_ARGS='--build-arg YTDLP_VERSION=2026.08.19' -> extra docker build args
```

`tests/e2e/run.sh` uses `set -o pipefail`: grep `docker logs` only via `log_has`/`log_count` or inside `sh -c`, and pair every negative check with a positive signal from the running container.

`youtubedl_interval=false` makes the container run one download pass and then exit. Settings come from `youtubedl_*` and `WEBUI_*` env vars; defaults are in the `Dockerfile` and documented in `README.md`.

## Runtime architecture

1. **`/entrypoint.sh`** sets a system-only `PATH` for all root processes, runs every script in `/etc/cont-init.d/` in glob order (numeric prefixes set the order) and **aborts the container if one fails**. It then starts supervisord. Every file in `cont-init.d` must be executable (a unit test checks this).
   - `05-default-confs`: copies `/config.default/{args.conf,channels.txt}` into `/config` if missing, symlinks `/config/args.conf` to `/etc/yt-dlp.conf`, substitutes `$youtubedl_quality` in `/config.default/format`.
   - `07-updater`: removes the updater's supervisor conf unless `youtubedl_autoupdate=true`.
   - `10-update-args`: replaces `/config/args.conf` with the new default if it matches the md5 of an **old default**. **When you change `root/config.default/args.conf`, add the md5 of the previous default to `old_default_hashes`.**
   - `90-user-permissions`: refuses `PUID`/`PGID` 0, applies them to user `abc`, chowns `/config`, `/downloads`, `/var/log` and abc's HOME `/home/abc`. `/app` and the venv `/opt/venv` stay root-owned (root-owned parents, so abc cannot replace them); the venv is chowned only when the updater is enabled. Test changes here with a `PUID` other than 911.
   - `91-supervisor-credentials`: random socket username/password.
   - `95-webui` (after 90, so `abc` has its final PUID/PGID): removes the webui conf unless `youtubedl_webui=true` **and** `webui_security.py check-credentials`, run as abc via `setpriv --init-groups`, accepts the credentials (fail closed, logged). It prints variable names and paths only, never a value.
2. **supervisord** (root) runs `youtube-dl` (`youtube-dl.sh`, tees to `/var/log/youtube-dl/youtube-dl.log`), the optional `youtube-dl-updater` and `youtube-dl-webui` as `abc`, and the non-autostarted `terminate` as root. abc's programs get `PATH` (with `/opt/venv/bin`) and `HOME` via `environment=`. Supervisor looks up a bare `command=` in the program's `environment=` PATH if set, otherwise in supervisord's own (system-only) PATH; all commands use absolute paths (`/bin/bash`, `/opt/venv/bin/uvicorn`). Never give a root-run program an `environment=` PATH containing abc-writable directories.
   - `youtube-dl` has `stopasgroup`/`killasgroup`: stop and restart (web UI *Restart*, `POST /restart-youtube-dl`) send SIGTERM to the whole process group (`bash -c`, `youtube-dl.sh`, yt-dlp, `tee`). Without them only `bash -c` died and the old pass kept running next to the new one. The SIGKILL to the group follows only if `bash -c` still runs after `stopwaitsecs`, so a member that ignores SIGTERM (a user pre/post script with `trap '' TERM`) survives; an unexpected death of `bash -c` (no supervisord stop) does not reach the group at all.
3. All yt-dlp processes run with the WORKDIR `/config` as current directory, so relative output paths land in `/config`.

Env flags are compared as `[ "$var" = true ]` — never execute them (`if $var`).

### `youtube-dl.sh` (core download loop)
- Builds the yt-dlp command as a **bash array**; there is **no `eval`** (a test enforces this).
- Adds `--format` and `--download-archive /config/archive.txt` only if `args.conf` doesn't set them; `--cookies` when `/config/cookies.txt` exists.
- Every entry (a `channels.txt` line, the subscriptions feed, watch later) runs as its own yt-dlp process: `base_cmd`, the line's `| extra args`, the event flags, `--`, URL. The args are split by `ytdlp_args.py split` (shlex, NUL-terminated tokens); a line whose args cannot be parsed is skipped. Plain URLs are cleaned like yt-dlp's `--batch-file` reader did when they ran together (BOM, `;`/`]` comment lines, a trailing ` #comment`). The worst exit code is kept (101, stopped early on purpose, does not count).
- Dashboard events only when `[ "$youtubedl_webui" = true ]`, via `status_events.py` (stdlib only, `python3 -I`): `begin` (rotates `/config/.youtube-dl-status/events.jsonl` at 2 MiB, appends `run_start`, prints run id and nonce), `channel-start`/`channel-end` around each entry (nonce marker lines in the log; `channel-start` also writes the entry's flags), then `echo "@@ytdl:<nonce> pass_end"` and `end` (summarises the pass log into `run_end`; when the channel rows do not fit one 32 KiB event they go into `run_rows` events right before a `run_end` without `ch`, so `run_end` never fails because of the number of entries) right before the sleep. Every call fails open: no flags, and the pass runs as with the web UI off. The flags come only from `status_events.ytdlp_flags()`: `--print-to-file`, never `--print` (implies `--quiet`), no `playlist:` print stage, no dict nested in a dict template; `tests/test_ytdlp_contract.py` checks them against the pinned yt-dlp. Only lines carrying the nonce are trusted (titles can forge log lines); the nonce never leaves the server.
- Trusted code appends the event flags **after** the user's args (args.conf, `| args`) and before `--`; never route them through the validator or loosen it for them. One yt-dlp process per entry is deliberate (per-entry exit codes, `channel j of m`); `--break-on-existing`/`--max-downloads` therefore act per entry (documented in README).
- The interval is split into words for `sleep` (`1d 3h`); an invalid value falls back to 3h so passes never run back to back.
- `youtubedl_interval=false`: the script only runs `supervisorctl start terminate` (`terminate.sh` sends SIGQUIT to supervisord, which stops every program and exits 0, so the container exits 0) and then `sleep infinity`. Never stop programs from inside the script (`supervisorctl stop all`): it is in the process group supervisor stops as a whole, so it would kill itself before `terminate` starts and the container would never exit. Never let it exit there either: `autorestart` would begin a second pass before the shutdown.

### Web UI (`root/app/youtube-dl-webui/`)
- `youtube-dl-webui.py`: `create_app()` factory; `webserver` is created lazily via module `__getattr__` (uvicorn resolves it on startup). Paths live in the `PATHS` object so tests can redirect them.
- An HTTP middleware authenticates from the headers **before** routes and body parsing run; only `PUBLIC_PATHS` (`/favicon.ico`, `/static/app.js`, `/static/app.css`) are open, and the API token is accepted only on `TOKEN_ROUTES` (`POST /download`, `POST /api/download`, both answer JSON for token clients). Route dependencies authenticate again and drive CSRF. FastAPI's `/docs`/`/openapi.json` are disabled.
- `webui_security.py`: env-based `Config` (fail closed via `startup_error()`; `WEBUI_USERNAME`/`WEBUI_PASSWORD`/`WEBUI_API_TOKEN` may instead come from the file a `*_FILE` variable names, read by the web UI process as abc, trailing whitespace stripped; both set, or a missing/unreadable/empty/over 64 KiB file, refuses to start; values are never logged, only "X set from X_FILE"; the env reaches uvicorn unchanged: entrypoint -> supervisord -> `os.environ.copy()` + `environment=`), Basic/Bearer auth with `compare_digest`, CSRF token + `Sec-Fetch-Site` check (Bearer requests exempt), URL validation (stripped, http/https only, optional `WEBUI_ALLOWED_DOMAINS`), security headers/CSP.
- Modules: `youtube-dl-webui.py` (routes), `webui_security.py`, `ytdlp_args.py`, `status_events.py` (event producer, shared `LogParser`), `dashboard.py` (aggregation), `jobs.py` (manual download queue).
- State lives in `/config/.youtube-dl-status/` (dir 0700, `events.jsonl` and `jobs/*.log` 0600, owned by abc): open with `O_NOFOLLOW` (file and directory), append with `O_APPEND` and one `write()` per event, read regular files only. Nothing is written there with the web UI off (e2e Scenario E checks it).
- Any new read route or status field must keep the nonce out: build JSON from explicit fields through `clean()`/`clean_url()`, serve log text only through `read_log_since()`/`scrub_log_line()`, and add the route to the tests that grep responses for the nonce (and to the e2e loop in Scenario A).
- `dashboard.py` (stdlib only): one `Dashboard` per process (uvicorn must keep a single worker) builds `GET /api/status` from `events.jsonl` (`EventLog`, plus `events.jsonl.1` once at startup) and the pass log (`PassLog`: the shared `LogParser` with the newest run's nonce, only while that run has no `run_end`). State is bounded (30 runs, 300 items, 7 days of download times, 50 jobs). `LineReader` returns complete lines only, follows rotation and `tee`'s truncation, and reads at most 1 MiB per poll. The JSON is built from explicit fields, every string through `clean()`/`clean_url()`; the nonce never leaves the server (tests grep every read response for it). ETag `"<boot>-<rev>"` with 304, `Cache-Control: no-store`; it runs in a worker thread under a lock.
- Log text for the browser (`GET /api/log/youtube-dl|download/{id}?since=` as `{offset, reset, more, text}`, and the plain `/log/*` routes) goes through `read_log_since()`: complete lines only (a `since` inside a line skips to the next one, so a cut line cannot reveal part of a nonce), and `scrub_log_line()` removes the nonce suffixes, channel markers, postprocess progress lines and `[info] Writing '{"v":1` lines and masks any other `@@ytdl:<hex>`.
- No invisible characters (bidi overrides, zero-width, separators, controls) in sources: write them as `\u` escapes (a test checks `root/`, `tests/`, `.github/`).
- `ytdlp_args.py`: shared by the UI (validation on save) and `youtube-dl.sh` (splitting). Validation walks tokens with **yt-dlp's own parser**, matching denied options by Option object (covers aliases like `--ppa`), then checks parsed values and resolves output paths like `YoutubeDL.get_output_path()` (relative to `/config`/`--paths home`). It is defense in depth, not a sandbox.
- Downloads run via `create_subprocess_exec` with `--` before the URL. Never use `create_subprocess_shell`/`shell=True` (a test greps for it).
- Manual downloads (`POST /download`, `POST /api/download`, retry, *Download now*) go through `jobs.py`'s `JobManager` (one per process, in the event loop): at most 20 waiting (429 with `Retry-After`), `WEBUI_MAX_PARALLEL_DOWNLOADS` (1-3) running, an active job with the same normalised URL is returned instead of a second one, an archived YouTube id answers `already` without starting yt-dlp unless forced. argv: base options, format, `--cookies` (a private copy `jobs/<id>.cookies`, deleted at the end: yt-dlp truncates and rewrites its cookie file on exit, so jobs must never get `/config/cookies.txt` itself), `--download-archive` (unless args.conf sets one; `--no-download-archive` when forced), the event flags, `--`, URL. Token answers are `{id, state, position, message}`. Job logs live in `/config/.youtube-dl-status/jobs/<uuid>.log` (newest 50; old ids are read from `/tmp/download_<id>.log`); `job_queued`/`job_start`/`job_end` events go to `events.jsonl`, and after a restart queued jobs are validated and queued again, running ones become `interrupted`.
- The job manager copies yt-dlp's output in 64 KiB chunks through an incremental UTF-8 decoder, never line by line (asyncio's 64 KiB line limit; progress without `--newline` is one endless line); only the live parser skips lines over 256 KiB, the log keeps everything. It drains the pipe to EOF and awaits the process. yt-dlp starts in its own session with stdin from `/dev/null`; cancel sends SIGTERM to that process group and SIGKILL 10 s later, and on an error or cancellation of the copy the group is killed, the pipe drained, then yt-dlp awaited (before Python 3.13, asyncio's `wait()` returns only once the pipe is closed). The lifespan shutdown stops running groups (uvicorn `--timeout-graceful-shutdown 3`, supervisor `stopwaitsecs=15`).
- `POST /restart-youtube-dl` (*Run now*) answers 409 while a pass runs unless `confirm=1`.
- Templates (`layout.html`, `dashboard.html` for `/` and the job page `/download/{id}`, `edit.html` for the three editors, `error.html`) get `base_path`, `csrf_token`, `readonly`, `page`, `download_id`, `parallel`, `max_queued`. Every POST form needs `<input type="hidden" name="csrf_token" value="{{ csrf_token }}">` (the e2e suite greps that exact markup). The CSP is `default-src 'none'` with `script-src`/`style-src`/`img-src`/`connect-src 'self'`: no inline scripts, no `style=` attributes or `<style>` blocks, no CDN, system fonts only. CSS lives in `static/app.css`, JS in `static/app.js` (both served by routes, not a StaticFiles mount, so they work behind prefix-stripping proxies); the script reads parameters from `data-*` attributes on `<body>`, renders server text only via `textContent`/DOM properties (never `innerHTML` and friends), clones icons from `<template id="icons">` and sets only widths/heights through the CSSOM. `tests/test_frontend_static.py` enforces this.
- The dashboard polls `GET /api/status` (ETag/304; 2 s while something runs, else 10 s; paused while the tab is hidden) and tails logs with `GET /api/log/...?since=`. Its forms degrade without JS: `POST /download` redirects to the job page, and browser navigations (`Accept: text/html`, not `/api/` or `/log/`) get HTML error pages (`error.html`, including the Run-now confirmation on 409) while API clients keep JSON. A refused config save re-renders the editor with the error (400).
- `TemplateResponse(request, name, context)` uses the Starlette 1.0 signature.
- `root/app/requirements.txt` is fully pinned (direct + transitive); Dependabot updates it.

## CI / release flow (`.github/workflows/`)

All workflows use the built-in `GITHUB_TOKEN`, minimal per-job `permissions`, checkouts without persisted credentials where nothing is pushed, and actions pinned by commit SHA.
- `ci.yml` (every push and PR): `test` (pytest against the yt-dlp version in `release-versions/latest.txt` with `YTDLP_CONTRACT_VERSION` set, pip-audit), `shellcheck`, `e2e` (`tests/e2e/run.sh`, amd64), `build-arm64` (build only). `publish-unstable` builds `:unstable` (`AUTOUPDATE=true`, updater rewritten to install yt-dlp from git, `git` added after `python3-pip` in the Dockerfile) **only on master and only after all four passed**. No images for other branches or PRs.
- `release.yml` (cron twice a day + manual, master only): job `verify` (read-only, no stored credentials) fetches the latest yt-dlp tag, validates its format and decides to build if the version changed, `:v<version>` is missing in GHCR, or on a manual run; it then runs pytest (with `YTDLP_CONTRACT_VERSION=<version>`, so the event-flag contract test fails instead of skipping and yt-dlp drift blocks publishing) and the e2e suite against exactly that version. Job `publish` (write access, never runs yt-dlp on the runner) builds and pushes `:latest` and `:v<version>` (`YTDLP_VERSION=<version>`, `AUTOUPDATE=false`) and only afterwards commits `release-versions/latest.txt` (`Release: v<version>`). Keep untrusted/new code out of jobs that hold write tokens.
- The repo is a GitHub fork: scheduled workflows stay disabled until enabled in the Actions tab, and GitHub disables them after 60 days without repository activity. The first `:latest` therefore comes from a manual *Release Images* run on master. In `publish`, outputs of `verify` are re-validated and passed only via `env`; QEMU runs with `cache-image: false`; the version commit is rebased onto the current master.
- yt-dlp is pinned via the `YTDLP_VERSION` build arg, not by editing the Dockerfile. Images are built for `linux/amd64` and `linux/arm64`. ffmpeg (yt-dlp/FFmpeg-Builds, `linux64`/`linuxarm64`) and deno are downloaded with retries, verified against the checksums published in the same release and installed root-owned.
